# VanillaCraft

Ванильный Minecraft-сервер и сайт-платформа к нему. Один репозиторий на три
части:

- `web/` — сайт на Next.js 15 (App Router, React 19), Prisma 6 + PostgreSQL.
  Личный кабинет, магазин, кейсы, мини-игры, админ-панель, API для плагина.
- `plugin/` — плагин `VanillaCore` для Paper 26.2, Java 25. Авторизация,
  наказания, чат, магазинные команды, боковая панель.
- `deploy/` — docker-compose, Caddy и скрипты выкатки на VPS.

Сайт — единственный источник правды. Плагин в базу не ходит: он спрашивает
сайт по HTTP и применяет ответ. Баланс, уровень, покупки, лимиты считает
сайт — плагин эту арифметику не повторяет.

## Документация

Читать до того, как трогать код:

- `docs/SPEC.md` — что за проект, экономика, уровни, наказания, платежи.
- `docs/PLUGIN.md` — команды в игре, устройство плагина, конфиг.
- `docs/DEPLOY.md` — обновление сайта и сервера, порядок и подводные камни.

Документацию правим вместе с кодом: если поведение изменилось, а в `docs/`
осталось старое — задача не доделана.

## Как проверять работу

Всё гоняется из `web/`:

```
npx tsc --noEmit          # типы
npm run build             # сборка Next.js
```

Сквозной прогон API (около 500 проверок) поднимает PGlite и собранный сайт.
Скрипт лежит в `scripts/e2e.mjs`, запускается против поднятого сайта:

```
BASE=http://127.0.0.1:3000 MC_SERVER_TOKEN=... node scripts/e2e.mjs
```

Новая возможность без проверок в `e2e.mjs` считается недоделанной. Проверки
пишем на настоящий сценарий, а не на «функция вернула не null».

Плагин собирается офлайн:

```
cd plugin && JAVA_HOME=/opt/jdk25 mvn -q -B -o package
```

## Стиль

- Комментарии, коммиты и сообщения игрокам — по-русски.
- Комментарий объясняет **почему** так сделано, а не пересказывает код.
  Хороший комментарий отвечает на вопрос «почему не проще?».
- Коммит: первая строка — что изменилось, дальше абзацами — зачем и какие
  решения приняты. Без списков «файл такой-то изменён».
- Новый код подстраивается под соседний: те же имена, та же плотность
  комментариев, те же приёмы.

## Чего делать нельзя

- **`docker system prune --volumes` и `docker volume prune` на VPS** сносят том
  `pgdata` вместе с базой сайта. Скрипты выкатки тома не трогают никогда.
- **Секреты в репозитории.** Токены бота, ключи панели, ключи касс и
  мониторинга живут только в `deploy/.env` на сервере. Если ключ засветился в
  переписке — его отзывают и выпускают новый.
- **Заливать jar на работающий игровой сервер.** Java читает классы из jar
  лениво: подменённый на ходу файл ломает уже запущенный процесс, игроки
  видят «unexpected error» на командах. Останов проверяется по `uptime`, а не
  по полю `state` — панель показывает `offline` и у зависшего живого сервера.
- **Трогать боевую базу напрямую.** Изменения схемы идут только через
  `prisma db push` из скрипта выкатки.
